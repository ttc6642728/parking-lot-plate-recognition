# 技术选型

## 1. 编程语言：Python 3.10+（推荐 3.12，已完整验证）

- 生态丰富，OpenCV/YOLO/PyQt5 都有一等公民支持；
- 适合作为大学生课程设计的入门语言，文档资源丰富。

## 2. 视觉栈

| 库 | 作用 | 选择理由 |
|---|---|---|
| OpenCV | 图像预处理、车牌兜底定位、摄像头 | 业界标准，社区庞大 |
| **HyperLPR3 + onnxruntime** | **车牌检测 + 字符识别（真实场景主力）** | 中文车牌专用端到端方案：YOLO 检测四点 → 透视矫正 → CNN+BiLSTM+CTC 整串输出。不依赖字符切分，对倾斜、光照、模糊鲁棒 |
| 内置模板匹配 OCR | 字符识别（离线兜底） | 零外部依赖；利用车牌结构先验（首位省份、次位字母），标准车牌特写图上表现好 |
| ultralytics (YOLOv8) | **车辆**检测 + 车牌区域粗定位 | 实时性好，部署简单。注意通用 COCO 权重不含 "plate" 类，实际流程是"检出车辆框 → 框内二次定位车牌" |
| pytesseract / Tesseract-OCR | 字符 OCR（可选补充） | 开源；需另装 C++ 引擎。实测在本项目场景下反而最弱（把 `粤C3Q8L1` 认成 `ZCSQSE`），仅作补充 |

### 2.1 为什么是"双引擎 + 仲裁"而不是选一个

两个方案各有硬伤，单独用都会在某一类输入上翻车：

| 方案 | 在什么输入上会错 | 实测证据 |
|---|---|---|
| 内置模板匹配 | 真实车牌。国标 GA36 专用字体与系统黑体差异大，单字模板相似度只有 0.3~0.4 | 清晰照片 `冀T15888` → 识别成 `津T1111`；17 种退化样本 0/17 |
| HyperLPR3 | 纯车牌特写、无车身上下文（训练分布不同） | 合成图 `沪B5M2N9` → `沪B5N2N9`、`川F2H6W8` → `桂F2H6W8` |

因此系统让两者都跑，再按**内置管线的自评置信度**仲裁：

- 内置自评高（≥0.55）→ 说明输入字体与模板同源 → 采信内置
- 内置自评低 → 说明模板匹配不上真实字形 → 采信 HyperLPR3

这个判据的本质是"字体是否同源"，可解释性强，也正好对应两个引擎的失效条件。
实测仲裁后：基础集 7/7、真实照片的 17 种退化增强 17/17。

> 任务书同时给出 HyperLPR / EasyPR 选项，本工程采用的 HyperLPR3 即其后续版本。

## 3. GUI：PyQt5

- 跨平台；
- 信号槽机制便于把识别 / 摄像头线程解耦；
- 内置 QTableWidget / QStackedWidget 满足后台数据展示需求。

## 4. 数据库：SQLite3

- Python 内置，零部署；
- 支持事务、索引，足以满足课程设计量级；
- 单文件方便答辩前打包。

## 5. 可视化：matplotlib

- 与 PyQt5 集成简单（FigureCanvasQTAgg）；
- 柱状图 / 折线图 / 饼图足够用于车流与营收统计。

## 6. 报表导出：openpyxl + pandas

- `pandas.to_excel` 支持多 sheet；
- `pandas.to_csv` 体积小便于邮件传输；
- 同时兼容中文编码（导出 CSV 默认 `utf-8-sig`）。
