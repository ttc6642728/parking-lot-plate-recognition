# 运行步骤

## 1. 环境

| 依赖 | 说明 |
|---|---|
| Python 3.10+ | 解释器（推荐 3.12） |
| pip 依赖 | `pip install -r requirements.txt` |
| Tesseract-OCR | OCR 引擎，**必须本机安装** |
| YOLO 权重（可选） | 放入 `models/`，首次运行也可自动下载 |
| USB 摄像头 | “摄像头实时识别”模式需要 |

## 2. 安装 Python 依赖

```bash
pip install -r requirements.txt
```

> 安装 PyQt5 可能较慢，若失败可换清华源：
>
> ```bash
> pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
> ```

## 3. 安装 Tesseract

### Windows
1. 下载 [Tesseract at UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki)
2. 安装时勾选 `Additional language data → Chinese (Simplified)`
3. 将 `C:\Program Files\Tesseract-OCR` 加入 `PATH`，或在 `config.py` 设置
   `TESSERACT_CMD = r"C:\Program Files\Tesseract-OCR\tesseract.exe"`

### Linux
```bash
sudo apt-get install tesseract-ocr tesseract-ocr-chi_sim
```

### macOS
```bash
brew install tesseract tesseract-lang
```

## 4. 环境自检（推荐先做）

```bash
python check_env.py
```

会依次检查：Python 依赖 → Tesseract 引擎 → YOLO 权重 → 测试图片 → 数据库 → OCR 实跑，
并给出**每一项的修复命令**。

配套工具：

| 脚本 | 作用 |
|---|---|
| `python fetch_tessdata.py` | 自动下载 Tesseract 语言包（eng + chi_sim）到 `tessdata` 目录 |
| `python make_samples.py` | 生成 6 张合成车牌测试图到 `data/images/` |

## 5. 启动

```bash
python main.py
```

- 首次启动会自动建库、创建默认账号、初始化总车位。
- 在登录界面输入 `admin / admin123` 进入主界面。

## 6. 演示流程（建议）

1. 用“图片识别”模块选择一张车牌图（放入 `data/images/`），验证识别流程。
2. 在“入场登记”模块手动输入车牌 → 确认入场，观察剩余车位变化。
3. 在“出场结算”模块输入同一车牌 → 查询 → 确认出场。
4. 在“数据统计”模块查看刚刚的记录是否被纳入统计。
5. 在“会员管理”新增一个会员，再次入场看是否显示“会员”标记。
6. 在“黑名单”加入车牌，再次入场时看是否弹窗。
7. 在“停车记录”导出 Excel / CSV。

## 7. 常见问题

先运行 `python check_env.py`，它会直接告诉你是哪一项出了问题。

| 问题 | 原因 / 解决 |
|---|---|
| `TesseractNotFoundError` | 装 Tesseract；或设置环境变量 `TESSERACT_DIR`（路径不能含中文） |
| `tesseract.exe` 返回 `3221225781` | **= `0xC0000135` = 缺 VC++ 运行库**。下载安装 [vc_redist.x64.exe](https://aka.ms/vs/17/release/vc_redist.x64.exe)，装完**重启电脑** |
| 提示缺少 `xxx.traineddata` | 运行 `python fetch_tessdata.py` 自动下载语言包 |
| `Illegal byte sequence` | Tesseract 安装路径含中文。程序会自动跳过它改用内置 OCR；想启用就改装到纯英文路径 |
| `Error opening data file ...` | tessdata 路径不对，检查 `TESSERACT_DIR/tessdata` 是否存在 |
| YOLO 下载失败 | 手动下载 `yolov8n.pt` 放到 `models/`；或不装也能跑（走 OpenCV 兜底） |
| 摄像头打不开 | 见下方「摄像头排查」，按顺序检查设备号 / 占用 / 隐私权限 |
| 日志出现 `DLL load failed ... onnxruntime_pybind11_state` | **PyQt5 比 onnxruntime 先加载导致**。必须在 `from PyQt5...` 之前先 `import onnxruntime`（`main.py` 已处理）。详见 `docs/识别准确率报告.md` 第五节 |
| 识别率低 | 先跑 `python eval_recognition.py --augment` 看是哪个引擎在起作用。若显示"内置管线"，说明 HyperLPR3 没生效，查上一行 |
| 图片读不出来（中文路径） | 已内置修复（`imread` 走 `np.fromfile`+`imdecode`），无需处理 |

### 摄像头排查

界面上的错误提示会直接说明属于哪一类。手动确认设备号的办法：

```python
# 在项目根目录执行
python -c "from core.camera import Camera; print(Camera.probe_devices(3))"
# 输出形如 [0] 或 [0, 1]，数字就是设备号
```

拿到设备号后，改 `config.py`：

```python
CAMERA_INDEX = 0        # 探测结果里选一个
CAMERA_BACKEND = "auto" # 默认即可；老驱动可试 "msmf"
```

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"没找到可用的摄像头设备" | 设备号不对 / 未连接 / 被禁用 | 用上面的探测命令确认编号；笔记本检查相机快捷键（Fn + F8 之类） |
| 提示"能打开但取不到画面" | 设备被其他程序独占 | 关闭微信、腾讯会议、QQ、浏览器视频页后重试 |
| 探测结果为空 | 系统层面没识别到设备 | Windows「设置 → 隐私 → 相机」允许桌面应用访问；设备管理器看是否报错 |

> 摄像头采集与识别都在后台线程，打开时界面不会卡住；从点击到出画面约 1~2 秒属正常
> （首次还要等模型预热，状态栏会显示"正在打开…"）。切回「图片识别」模式会自动释放设备。


### 关于演示模式

`config.py` 中 `DEMO_MODE` **默认为 `False`**（提交 / 正式运行的正确状态）：

- `False`：只输出真实识别结果，识别不到就提示"未检测到车牌"；
- `True`：识别失败时会**随机生成一个格式合法的车牌**并提示"识别成功（演示模式）"，
  仅用于环境不完整时保证业务流程能走通。

> ⚠ 答辩若临时开启 `True`，务必主动说明"这是演示兜底，不是识别结果"，
> 否则会被误认为识别功能造假。正常提交请保持 `False`。
